# Notes for Claude

This repo is the Prairie Valley Church website (owner: Josh Slater, jslater1226). GitHub Pages publishes `dist/` from `main` through `.github/workflows/pages.yml` (preview: https://jslater1226.github.io/prairie-valley-church-site/). Netlify was the first host but its credits ran out on 2026-11-23, so it is no longer used. The repo is public because GitHub Pages is free only for public repos on this plan.
- `NOINDEX=True` in `build/make.py` keeps the preview out of search engines. Set it to False at launch.
- Batch edits and push once per round. Every push triggers a deploy.

- Edit `build/` (mostly `build/copyedit.txt` and `build/make.py`), run `cd build && python3 make.py`, check the result, then commit `build/` and `dist/` together and push to `main`.
- Do not change DNS, Netlify settings, or repo visibility without Josh's yes.
- Do not commit under Josh's name or email. Commits are signed as Claude.

- Events are no longer in the page code. They live in `data/events.json` and are edited through Pages CMS (config in `.pages.yml`, flyer images in `data/media/`). The deploy workflow validates the JSON and copies `data/` into the published site. Do not move `data/` under `build/` or `dist/`, because `make.py` deletes `dist/` on every build.
- Sermon series buttons (`data/series.json`), the ministries list (`data/ministries.json`) and the site-wide service times, address and phone (`data/site.json`) are also edited through Pages CMS (`.pages.yml`). They are rendered into the page at build time only, with no page-load script. `make.py` reads `data/site.json` into `CFG` and fills the `{{TOKENS}}` everywhere they appear. Ministry text is inserted after that step on purpose, so what staff type in a ministry row is what shows (it does not follow the site-wide times). The workflow validates all four JSON files. Only events are still loaded by the page at load time.
- The deploy workflow now builds the site itself (`pip install pillow`, then `cd build && python3 make.py`) and retries the deploy up to twice more (after 45 s and 60 s waits) if it fails. `dist/` is still committed as a fallback, but the published site comes from the CI build.
- Staff and elders live in `data/people.json` (Pages CMS form "Staff and elders"). `build/copyedit.txt` renders them at build time and processes photos from `data/media/` (EXIF rotation fixed, square crop biased to the top, 256px; the optional elders group photo is capped at 1500px wide) into `dist/assets/people/`. Elders show as photo cards only when every elder has a photo (an elder who is also staff reuses the staff photo); otherwise the text list shows. A missing photo prints a WARNING and falls back to initials.
- `build/strip_media.py` runs in the workflow after `data/` is copied and re-saves everything under `dist/data/media` without EXIF/GPS, capped at 1600px wide. The original uploads are still in the public repo.
- The YouTube embed uses the channel's live-streams playlist (`UULV` + channel id), not the all-uploads playlist (`UU`), because a new Short became the newest item in the uploads playlist.
- The Grow page (`/grow/`) is built from `data/grow.json` by `build/grow.py` (Pages CMS form "Grow page"): sermon quotes, a monthly newsletter archive (PDFs uploaded to `data/media/`), and an optional discussion-questions link. It is derived from the finished home page (shared header, footer, styles and scripts) with `<base href="../">`, so relative links and `#section` links resolve from the site root. With no content, no page, no menu link and no sitemap entry are produced. A missing PDF prints a WARNING and drops its button. Each issue with a PDF also gets a Download PDF button, and the home page footer links the latest PDF (Explore column). Do not add placeholder or invented quotes: Josh picks which words from his sermons go up.
